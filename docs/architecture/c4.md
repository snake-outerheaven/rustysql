# Diagramas C4

O [modelo C4](https://c4model.com) descreve um sistema em quatro níveis de zoom: **Contexto**, **Contêineres**,
**Componentes** e **Código**. Os diagramas abaixo usam `flowchart` do Mermaid (a notação C4 nativa do
Mermaid ainda é experimental e não renderiza em todo lugar). Convenção: retângulo = componente
próprio; cilindro = armazenamento; elipse = sistema externo ou pessoa.

## Nível 1: Contexto do sistema

Quem usa o rustysql e com o que ele conversa.

```mermaid
flowchart TB
    dev(["Desenvolvedor Rust<br/><i>[Pessoa]</i><br/>embute a biblioteca no seu programa"])
    usr(["Usuário do terminal<br/><i>[Pessoa]</i><br/>explora dados com SQL"])
    sys["<b>rustysql</b><br/><i>[Sistema de software]</i><br/>banco relacional embutido, transacional,<br/>com SQL, índices B+tree e recuperação de falhas"]
    os(["Sistema operacional<br/><i>[Sistema externo]</i><br/>arquivos e fsync"])

    dev -- "chama a API Rust" --> sys
    usr -- "digita SQL no REPL<br/>ou executa um script .sql" --> sys
    sys -- "lê e grava arquivos<br/>força o disco (fsync)" --> os
```

## Nível 2: Contêineres

Num banco embutido, "contêiner" é uma unidade executável ou de dados distinta.

```mermaid
flowchart TB
    subgraph proc["Processo do usuário"]
        cli["<b>rustysql (binário)</b><br/><i>[Executável Rust]</i><br/>REPL e modo script (src/main.rs)"]
        lib["<b>rustysql (biblioteca)</b><br/><i>[Crate Rust]</i><br/>Database, Session, motor SQL,<br/>armazenamento e concorrência"]
        app["<b>Seu programa</b><br/><i>[Executável Rust]</i>"]
    end
    data[("<b>banco.db</b><br/><i>[Arquivo]</i><br/>páginas de 4 KB: catálogo, heaps, B-trees")]
    wal[("<b>banco.db.wal</b><br/><i>[Arquivo]</i><br/>um registro por transação commitada")]

    cli -- "usa" --> lib
    app -- "usa" --> lib
    lib -- "lê/grava páginas<br/>(só no checkpoint)" --> data
    lib -- "anexa registros<br/>(a cada commit)" --> wal
```

| Contêiner | Tecnologia | Responsabilidade |
|---|---|---|
| Biblioteca | Rust, `parking_lot` | todo o banco |
| Binário | Rust | REPL interativo e execução de scripts com tempos por comando |
| `banco.db` | arquivo de páginas | estado commitado no último checkpoint |
| `banco.db.wal` | arquivo de log | commits desde o último checkpoint |

## Nível 3: Componentes da biblioteca

### 3a. Visão geral

```mermaid
flowchart TB
    api["<b>API pública</b><br/>Database · Session · Options<br/><i>db.rs</i>"]

    subgraph sql["Motor SQL"]
        direction LR
        parser["<b>Lexer + Parser</b><br/>texto → AST"] --> planner["<b>Planejador</b><br/>AST → plano<br/>(índices, joins)"] --> executor["<b>Executor</b><br/>operadores Volcano"]
        evalc["<b>Avaliador</b><br/>expressões, NULL"]
    end

    subgraph conc["Controle de concorrência"]
        direction LR
        sched["<b>Escalonador</b><br/>admissão por prioridade"]
        locks["<b>Gerenciador de locks</b><br/>2PL + deadlock"]
        txn["<b>Transação</b><br/>undo + WAL pendente"]
    end

    subgraph store["Armazenamento"]
        direction LR
        cat["<b>Catálogo</b><br/>tabelas e índices"]
        heap["<b>Heap</b><br/>slotted pages"]
        btree["<b>B+tree</b><br/>latch crabbing"]
        walc["<b>WAL</b><br/>redo + CRC"]
    end

    subgraph base["Base"]
        pool["<b>Buffer pool</b><br/>latches · pin · no-steal"]
        disk["<b>Disco</b>"]
    end

    api --> sql
    api --> conc
    sql --> store
    api --> store
    conc --> walc
    heap --> pool
    btree --> pool
    pool --> disk
```

### 3b. Dentro do componente "Motor SQL"

```mermaid
flowchart LR
    text["texto SQL"] --> lexer["lexer<br/>tokens"]
    lexer --> parser["parser<br/>Statement"]
    parser --> ast["ast"]
    ast --> plan["plan<br/>Plan{Node, Scope}"]
    plan --> exec["exec<br/>RowIter"]
    ast -. "Expr" .-> eval["eval<br/>bind → BExpr"]
    plan -. "bind" .-> eval
    exec -. "eval" .-> eval
    exec --> result["linhas"]
    cat["catalog<br/>TableInfo/IndexInfo"] --> plan
    cat --> exec
```

### 3c. Dentro do componente "Controle de concorrência"

```mermaid
flowchart TB
    session["Session.run_in_txn"] --> begin["Inner::begin<br/>portão de checkpoint (RwLock leitor)"]
    begin --> admit["Scheduler::admit<br/>fila de prioridade → Permit"]
    admit --> lock["Inner::lock<br/>LockManager::acquire_with"]
    lock -. "ao bloquear:<br/>Permit::yield_slot" .-> admit
    lock --> work["executa o comando<br/>(Txn: undo + WAL pendente)"]
    work --> commit["Inner::commit<br/>Wal::append_commit → release_all"]
```

### 3d. Dentro do componente "Armazenamento"

```mermaid
flowchart TB
    subgraph tabela["Uma tabela"]
        hf["HeapFile<br/>cadeia de páginas"]
        ix1["BTree pk_t"]
        ix2["BTree idx_x"]
    end
    row["linha (Vec&lt;Value&gt;)"] -- "encode_row" --> hf
    row -- "value_key (+ RowId)" --> ix1 & ix2
    ix1 & ix2 -- "RowId" --> hf
    hf & ix1 & ix2 --> pool["BufferPool"]
```

## Nível 4: Código

O nível de código **é** o código: cada módulo tem a sua página em [`../modules/`](../modules/README.md)
e a API completa em rustdoc (`cargo doc --no-deps --open`). As estruturas de dados centrais:

| Estrutura | Módulo | Papel |
|---|---|---|
| `Frame` / `PageRef` / `PageReadGuard` / `PageWriteGuard` | `bufferpool` | página + pin + latch |
| `RowId { page, slot }` | `heap` | endereço físico de uma linha |
| `Node { Leaf, Internal }` | `btree` (privado) | nó da B+tree |
| `WalOp`, `Batch` | `wal` | operação de redo; registro de commit |
| `Txn`, `Undo`, `Mark` | `txn` | transação em andamento |
| `Plan { node, scope }`, `Node` | `plan` | plano de execução |
| `Permit`, `Entry` | `sched` | vaga de execução; item da fila de prioridade |
